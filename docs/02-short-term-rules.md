# 단기 축: 추세추종·자동화 규칙 (터틀 스타일)

## 진입(매수)

- 20거래일 신고가(종가 기준) 돌파 시 매수
- 필터: MA50 > MA200 (정배열)일 때만 신호 채택
- 국장은 유동성 필터(일평균 거래대금 상위 30% 이내) 추가 권장

## 청산(매도)

- 추세추종 청산: 10거래일 신저가 하향 이탈
- 손절: 진입가 대비 -2×ATR
- 트레일링 스탑: 보유 중 최고가 대비 -2×ATR

## 포지션 사이징

- 1거래당 리스크 = 계좌(단기 축) 자본의 1~2%
- 수량 = 리스크 허용액 ÷ (진입가 - 손절가)

## 자동화 아키텍처

| 단계 | 내용 |
|---|---|
| 데이터 수집 | 국장(증권사/KRX API), 미장(yfinance 등) 일봉 자동 수집 |
| 스크리닝 | 매일 장마감 후 관심종목 대상 조건 자동 계산 |
| 신호 생성 | 조건 충족 종목 + 손절가/수량 자동 계산 |
| 알림 | 조건 충족 시 카카오톡/슬랙/이메일 실시간 푸시 |
| 기록 | 노션 매매일지 API로 매수/매도 시점·근거·결과 자동 기록 |
| 실행 | 초기: 알림만 → 수동 주문. 안정화 후 자동주문 API 연동 검토 |

## 검증 절차

1. `backtest/trend_following_backtest.py`의 `generate_sample_data()`로 로직
   자체 정상 동작 확인 (완료)
2. 실제 종목 OHLCV 데이터로 `run_backtest_from_csv()` 실행
3. `grid_search()`로 파라미터(진입/청산 기간, ATR 배수) 최적 조합 탐색
4. `walk_forward_validate()`로 과최적화 여부 검증
5. 최소 1~3개월 모의 신호 로그 축적 후 실거래 적용 검토
